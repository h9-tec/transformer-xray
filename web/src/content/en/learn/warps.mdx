# Warps: the real unit of execution

You write code for one thread. The hardware does not run one thread. It runs
**32 at a time**, in lockstep, sharing a single instruction stream. That group
is a warp, and most GPU performance stories are warp stories.

<Junior>
  Picture 32 people reading the same sheet of instructions aloud together.
  They can each hold different numbers, but they all do the same operation
  at the same moment. Now the sheet says "if your number is odd, double it;
  otherwise add one". The group cannot split up. So first everyone with an odd
  number acts while the others wait, then everyone with an even number acts
  while the first group waits. Both halves took a turn; the warp did twice the
  work for the same result. That is **divergence**.

  Divergence is not a bug, but it is a cost. The lesson's exercise,
  `odd_even`, has two genuinely different loops for odd and even elements.
  You cannot remove the branch, but you can decide which thread handles
  which element, so that every warp sees only odd or only even work.
</Junior>

<Senior>
  A warp executes under an **active mask**. At a branch, the hardware runs the
  taken path with the mask of lanes that took it, then the other path with the
  complement, then reconverges. Cost is proportional to the union of paths,
  not the longest one. The simulator counts every warp instruction executed
  under a partial mask and reports it as *divergent instructions*; the hero on
  the landing page draws exactly this.

  Divergence is only a problem *within* a warp. A condition that is uniform
  across the 32 lanes, such as `(threadIdx.x / 32) % 2`, costs nothing: the
  whole warp takes one path. Modern compilers turn tiny if/else bodies into
  predicated selects, so a one-line branch may not diverge at all on real
  hardware; the simulator counts every partially-masked instruction. The
  exercise's arms are eight-step loops precisely so the cost is real.
</Senior>

```cuda
if (threadIdx.x % 2)          // splits every warp: 16 lanes each way
if (threadIdx.x < 16)         // splits every warp in half
if ((threadIdx.x / 32) % 2)   // uniform: a whole warp agrees, no divergence
```

The early `return` for `i >= n` looks like a branch too, and it is. It does
not diverge here only because 1024 threads exactly cover 1024 elements, so
every lane takes the same side. The trick the exercise wants is a remap:
nothing says thread `i` must own element `i`.
