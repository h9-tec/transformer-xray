# Tiled matmul: reuse every float 32 times

Matrix multiply is the transformer. QKV projections, the attention output,
both MLP layers, the logits: all the same kernel with different shapes. The
naive version is correct and spends almost all its time waiting for memory.
Tiling is the one idea that fixes it, and it is the idea behind cuBLAS.

<Junior>
  Picture a block of 32×32 threads computing a 32×32 patch of C. Thread
  $(i, j)$ walks the whole $K$ dimension reading $A[i, k]$ and $B[k, j]$.
  Now notice that thread $(i+1, j)$, one row down and in a different warp,
  reads the **exact same** $B[k, j]$. All 32 rows of the block read it, so
  the block fetches every element of its B strip thirty-two times. (Within
  one warp the 32 threads of a row read the same $A[i, k]$ too, but that is
  one broadcast request; the waste is across warps and across blocks.)

  Shared memory is the fix: the block loads a 32×32 tile of A and a 32×32
  tile of B into it once, then each thread reads from the scratchpad. Every
  loaded float is reused 32 times. The exercise `matmul` starts from the naive
  kernel; your job is to add the two tiles and the two barriers.
</Junior>

<Senior>
  Traffic for $C = AB$ with $M \times K$ and $K \times N$:

  $$
  \text{naive} \approx 2MNK \cdot 4\,\text{B}, \qquad
  \text{tiled} \approx \frac{2MNK}{\text{TILE}} \cdot 4\,\text{B}
  $$

  At the model's QKV shape ($128 \times 192 \times 576$) that is 113 MB
  against 3.5 MB for a 28 MFLOP job. Two barriers per k-step are required:
  the first so no thread reads a tile before every element is staged, the
  second so no thread overwrites the tile for step $k_0 + \text{TILE}$ while a
  slower warp is still multiplying from it. Remove the second and the race
  detector will show you exactly which lines collide.

  Real GEMMs go further: register tiling (each thread computes a small
  sub-block), double buffering, and tensor-core instructions. All of them
  are refinements of this reuse argument.
</Senior>

```cuda
__shared__ float As[TILE][TILE];
__shared__ float Bs[TILE][TILE];
for (int k0 = 0; k0 < K; k0 += TILE) {
  // 1. every thread stages one element of A and one of B into the tiles
  // 2. barrier: the tiles must be complete before anyone reads them
  // 3. each thread accumulates TILE products from the tiles
  // 4. barrier: everyone must be done reading before the next overwrite
}
```

The traffic target asks for at least 12× less than the naive kernel at the
64³ exercise size; the real kernel achieves about 16×, and the gap to the
ideal 32× is the C stores and the small size.
