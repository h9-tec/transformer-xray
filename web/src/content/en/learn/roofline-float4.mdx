# Roofline and float4

You now have twelve kernels' worth of intuition. The roofline turns it into
one picture: for any kernel, how fast *could* it go, and which wall is it
leaning on?

<Junior>
  Every GPU has two speed limits: how many floating-point operations it can
  do per second, and how many bytes it can move per second. A kernel that
  does a lot of math per byte it loads is held back by the first limit. A
  kernel that does little math per byte is held back by the second. The
  ratio, FLOPs per byte, is called **arithmetic intensity**, and it decides
  which limit applies.

  GELU does about 20 operations per float and moves 8 bytes per float: an
  intensity of 2.5. That is far below the point where arithmetic matters, so
  GELU is memory-bound, and the only ways to make it faster are to move
  fewer bytes or to move them better. The exercise `gelu_residual` does the
  first: the residual add and the GELU run as two passes in the starter,
  with the sum written to global memory and read straight back. Fuse them
  and 20 bytes per element become 12.
</Junior>

<Senior>
  The roofline model: attainable FLOP/s $= \min(\text{peak FLOP/s},\ I \times
  \text{bandwidth})$ where $I$ is intensity in FLOP/byte. The ridge point
  $I^* = \text{peak}/\text{bandwidth}$ is where the two limits meet; for a
  laptop RTX it is on the order of 50 to 100 FLOP/byte. Every elementwise
  kernel in the model (GELU, residual add, LayerNorm) sits well left of the
  ridge; the matmuls at the model's shapes sit near it; only large GEMMs
  reach the compute roof.

  Fusion raises intensity: the same 22 FLOPs over 12 bytes instead of 20.
  Vectorization (`gelu_forward_f4`, the real kernel below) does not change
  intensity at all; it changes the number of memory *instructions* and warp
  requests the memory system must track, which is what limits a memory-bound
  kernel once its accesses are already coalesced. The repo's measured results
  show the float4 variant ahead of the scalar one. Production stacks do both:
  fuse the elementwise tail of a layer into one kernel, then vectorize it.
</Senior>

```cuda
// two passes: a, b read; tmp written; tmp read; y written   = 20 B per element
// one pass:   a, b read;                       y written   = 12 B per element
// same 22 FLOPs either way: intensity 1.1 against 1.8 FLOP per byte
```
